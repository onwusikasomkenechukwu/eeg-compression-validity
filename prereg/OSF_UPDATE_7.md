## Justification tab

> Seventh update, submitted after both Siena runs registered in update 6 finished (patient-specific arm 160 jobs, 2026-11-24T00:33Z; cross-patient arm 70 jobs, 2026-11-24T05:57Z; no failures) and before any of their results were inspected. As on CHB-MIT (update 5), the runner logs showed warnings from PyTorch's CUDA memory allocator (an allocation failed, cached memory was released and the allocation was retried): 5 in the patient-specific arm and 12 in the cross-patient arm. Because memory pressure can change which deterministic convolution algorithm cuDNN uses, and with it floating-point rounding, this update applies update 5's repeatability check to the affected Siena jobs. Nothing in the design, analysis or decision rule changes. Siena results seen so far: none (only the runner logs, i.e. job completion, run time, warnings and errors, were read).

## Page 6: Analysis Plan → Inference criteria (add at the end)

> Update 7. Repeatability under memory pressure, Siena. The jobs whose runner log showed allocator warnings before they finished are rerun with the same code (commit 3ff0469), environment and command as their arm's run, into a separate folder, one job at a time per GPU: the patient-specific jobs on one GPU and the cross-patient jobs on the other, nothing else on either. Patient-specific arm: PN14 fold 1 seed 0 (1 job). Cross-patient arm: fold 0 seeds 0 and 4; fold 1 seed 0; fold 4 seeds 0 and 4 (5 jobs). Each warning is attributed to the next job its runner finished; because each runner ran 2 jobs at once, the attribution is approximate. Each rerun is compared with the original, array by array (saved weights, normalization, QAT state and all score arrays), by exact equality, without inspecting any metric; where arrays differ, only the largest absolute difference per array is recorded. Whatever the outcome, each arm's analysis uses its original jobs as registered in update 6, and the outcome is reported per arm: if all match, as "identical"; otherwise, as the number of jobs that differ and the largest differences, and the paper describes those jobs as reproducible to floating-point rounding rather than bit-identical. The reruns are then deleted.
