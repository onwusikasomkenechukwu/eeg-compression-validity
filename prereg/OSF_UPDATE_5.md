# OSF registration update 5: repeatability check of jobs run under GPU memory pressure

**Status:** submitted on OSF on 2026-11-19, after the workstation run finished and before any analysis of it (including the W4A8/FP16 rescore). Same mechanics as before: each paragraph was appended to the end of its field. Outcome (2026-11-22): all 18 reruns identical to the originals, array by array; reruns deleted.

## Justification tab

> Fifth update, submitted after the confirmatory run finished (all 690 jobs, 2026-11-19T18:13Z, no failures) and before any of its results were inspected. While the run was in progress, the runner logs showed 97 warnings from PyTorch's CUDA memory allocator (an allocation failed, cached memory was released and the allocation was retried). No job failed. Under memory pressure cuDNN may use a different deterministic convolution algorithm, which can change floating-point rounding, so jobs that ran under pressure may not be bit-identical to the same job run alone. Update 3's repeatability check ran one job alone and did not cover this. This update adds a check of the affected jobs. Nothing in the design, analysis or decision rule changes. Ahlawat results seen so far: none (only the runner logs, i.e. job completion, run time, warnings and errors, were read).

## Page 6: Analysis Plan → Inference criteria (add at the end)

> Update 5. Repeatability under memory pressure. The 18 jobs whose runner log showed allocator warnings before they finished are rerun one at a time per GPU (2 jobs at a time, nothing else on either GPU), with the same code (commit 58d8708), environment and command as the confirmatory run, into a separate folder: chb02 fold 0 seeds 0, 1, 3, 4; chb03 fold 6 seed 1; chb04 fold 0 seeds 1, 3; chb04 fold 2 seed 4; chb06 fold 0 seed 0; chb06 fold 1 seed 4; chb06 fold 2 seed 2; chb09 fold 1 seed 1; chb10 folds 0 and 1 seed 2; chb17 fold 0 seed 1; chb21 fold 0 seed 0; chb21 fold 1 seed 1; chb21 fold 2 seed 2. Each warning is attributed to the next job its runner finished; because each runner ran 2 jobs at once, the attribution is approximate. Each rerun is compared with the original, array by array (saved weights, normalization, QAT state and all score arrays), by exact equality, without inspecting any metric; where arrays differ, only the largest absolute difference per array is recorded. Whatever the outcome, the confirmatory analysis uses the original 690 jobs as registered, and the outcome is reported: if all 18 match, as "identical"; otherwise, as the number of jobs that differ and the largest differences, and the paper describes the run as reproducible to floating-point rounding rather than bit-identical for those jobs. The reruns are then deleted.
